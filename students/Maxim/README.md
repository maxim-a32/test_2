# DevOps Lab: CI/CD деплой статичного сайту на Render

## Призначення
Простий статичний вебсайт на базі вебсервера Nginx, запакований у Docker-контейнер. Проєкт демонструє повний цикл автоматизованої збірки Docker-образу та безперервного розгортання (CI/CD) у хмарну платформу Render.

**Публічне посилання на робочий застосунок:** https://devops-h16g.onrender.com

## Локальний запуск
Для локальної перевірки застосунку в Docker перейдіть у папку `students/Maxim/` та виконайте команди:

1. **Збірка Docker-образу:**
   ```bash
   docker build -t maxim-app .
   ```

2. **Запуск контейнера:**
   ```bash
   docker run -p 8080:80 maxim-app
   ```

Після запуску сайт буде доступний у браузері за адресою: `http://localhost:8080`.

---

## Деплой та CI/CD
Замість інфраструктури AWS (EC2 + Terraform) для хостингу використано хмарну платформу **Render** (конфігурація сервісу описана в `infra/render.yaml`).

Автоматичний пайплайн налаштовано через **GitHub Actions** (`.github/workflows/deploy.yml`) і спрацьовує при кожному `push` у гілку `main`, якщо змінюються файли у папці `students/Maxim/`:
1. **Build & Push:** GitHub Actions авторизується на Docker Hub, збирає новий образ із `Dockerfile` та завантажує його в репозиторій `maxima32/maxim-app:latest`.
2. **Deploy:** Після успішного пушу образу пайплайн надсилає POST-запит на Render Deploy Hook, що запускає оновлення вебсервісу.

## Змінні середовища та секрети
* **Змінні контейнера:** вебсервер Nginx працює на стандартному внутрішньому порту `80` (Render визначає його автоматично з інструкції `EXPOSE 80` у `Dockerfile`).
* **GitHub Secrets (налаштовані в репозиторії для роботи CI/CD):**
  * `DOCKER_USERNAME` — ім'я користувача в Docker Hub.
  * `DOCKER_TOKEN` — токен доступу для завантаження образів у Docker Hub.
  * `RENDER_DEPLOY_HOOK` — секретне URL-посилання для тригеру оновлення сервісу на Render.
